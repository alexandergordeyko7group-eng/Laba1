Лабораторная №1 «Создание процессов» + дополнительное задание CMake

Все исходники на C++17, без комментариев в коде.

Main.cpp — ввод данных, запуск Creator и Reporter, ожидание и вывод файлов.
Creator.cpp — ввод сотрудников и запись бинарного файла.
Reporter.cpp — чтение сотрудников, сортировка по номеру и создание отчёта.
employee.h — общая структура записи.
CMakeLists.txt — сборка трёх программ.

Требуется Windows, CMake и компилятор C++.
Для Visual Studio нужен компонент «Разработка классических приложений на C++».

Откройте терминал в папке проекта и выполните:
cmake -S . -B build
cmake --build build --config Debug

Запуск в PowerShell:
cd build\bin
.\Main.exe

Запуск в cmd:
cd build\bin
Main.exe

Для MinGW, если g++ и mingw32-make доступны в PATH:
cmake -S . -B build-mingw -G "MinGW Makefiles"
cmake --build build-mingw
cd build-mingw\bin
.\Main.exe

Запускайте Main из папки bin. Все три exe должны лежать вместе.
При использовании MinGW необходимые DLL компилятора должны быть в PATH.

Пример интерактивного ввода (вводите по мере появления запросов):
employees.bin
3
3 Ivan 40
1 Anna 32
2 Petr 20
report.txt
10

Creator принимает для каждого сотрудника номер, имя и часы.
Main показывает сотрудников в порядке ввода.
Reporter сортирует их по номеру по возрастанию и считает зарплату: часы * ставка.
Отчёт для примера:
Отчет по файлу «employees.bin»
Номер сотрудника, имя сотрудника, часы, зарплата
1, Anna, 32.00, 320.00
2, Petr, 20.00, 200.00
3, Ivan, 40.00, 400.00

Ограничения:
Имя сотрудника — одно слово, до 9 байт; для простоты используйте латиницу.
Десятичные числа вводите через точку. Часы и ставка неотрицательные.
Для файлов используйте латинские названия, например employees.bin и report.txt.
Пробелы в путях допустимы. Файл отчёта должен отличаться от бинарного файла.
Отчёт записывается в UTF-8. При повторном запуске файлы с теми же именами перезаписываются.
Формат бинарного файла — записи employee целиком, включая выравнивание структуры;
он предназначен для трёх программ, собранных одним компилятором для одной архитектуры.

В Main используется CreateProcessA для создания процессов и
WaitForSingleObject с INFINITE для ожидания завершения каждого из них.
После ожидания проверяется код завершения и закрываются оба дескриптора.
